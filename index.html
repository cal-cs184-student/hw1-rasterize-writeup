Task 1: Drawing Single-Color Triangles

Implementation

I rasterized each triangle by first computing an axis-aligned bounding box from the minimum and maximum x and y coordinates of its three vertices. I clipped the bounding box to the framebuffer boundaries and iterated only over the pixels within that region.

For each pixel, I tested the sample at the center of the pixel, (x+0.5, y+0.5). I used a signed edge function on each of the triangle's three edges to determine which side of each edge contained the sample. The smaple was considered inside the triangle when all three edge-function values were non-negative or when all three were non-positive.

Checking both sign directions allows the algorithm to rasterize triangles with either clockwise or counterclockwise vertex ordering. I used inclusive comparisons, >= and <=, so a sample directly on a triangle boundary is also included. If the sample passed the three edge tests, I called fill_pixel() using the pixel coordinates and the triangle's color.

Efficiency

The algorithm does not iterate over entire frame buffer. It examines only the samples inside the triangle's boudning box. If the bounding box has width \(B_w\) and height \(B_h\), the algorithm performs \(B_w B_h\) point-in-triangle tests. Each test uses three constant-time edge-function calculations, so the total running time is \(O(B_w B_h)\). Therefore, the algorithm is no worse than an algorithm that checks every sample within the triangle's bounding box.

Task 2: Antialiasing by Supersampling

Algorithm and Data Structure

I implemented supersampling by storing multiple color samples for every output pixel. The sample buffer contains width * height * sample_rate Color objects, with the subsamples for each pixel stored contiguously. For a sample rate of \(r\), I used a \(\sqrt{r} \times \sqrt{r}\) uniform grid inside each pixel.

During triangle rasterization, I performed the edge tests independently at every subpixel location. Covered subsamples received the triangle color, while uncovered subsamples retained the color already in the sample buffer. After all primitives were rasterized, I resolved the sample buffer by averaging the subsample colors belonging to each pixel and writing the result into the RGB framebuffer.

Rasterization Pipeline Changes

I resized the sample buffer whenever the framebuffer dimensions or sample rate changed. I modified fill_pixel() to fill every subsample of a pixel so that points and lines would continue to render correctly. Triangles instead write to individual subsamples. Finally, I updated resolve_to_framebuffer() to average the subsamples and convert their floating-point color components into 8-bit RGB values.

Why Supersampling Helps

With one sample per pixel, a triangle edge produces a binary decision: the entire pixel is either inside or outside. This produces jagged edges and can miss very thin features. Supersampling approximates the fraction of each pixel covered by the triangle. Averaging the covered and uncovered samples produces intermediate edge colors, making diagonal edges and narrow triangle corners appear smoother.

Results

At sample rate 1, diagonal boundaries show abrupt stair-step patterns because each pixel receives only one binary coverage decision. At sample rate 4, the additional samples capture partial coverage and create smoother boundary colors. At sample rate 16, the coverage estimate is more precise, so the thin triangle corner and diagonal edges appear smoother and more continuous. The visual improvement comes with higher runtime and memory usage because more samples must be stored, tested, and averaged.

Task 4: Barycentric coordinates

Barycentric coordinates describe the location of a point inside a triangle using three weights, \(\alpha\), \(\beta\), and \(\gamma\). Each weight represents how much influence one vertex has on the point, and the three weights satisfy:

\[ \alpha + \beta + \gamma = 1 \]

At the first vertex, the barycentric coordinates are \((1, 0, 0)\). At the second vertex, they are \((0, 1, 0)\), and at the third vertex, they are \((0, 0, 1)\). Inside the triangle, the weights smoothly vary between these values.

I calculated each weight using a ratio between a smaller signed triangle area and the signed area of the complete triangle. I then used the barycentric weights to interpolate the vertex colors:

\[ C = \alpha C_0 + \beta C_1 + \gamma C_2 \]

For each sample inside the triangle, I applied this equation separately to the red, green, and blue color components. A sample close to one vertex receives more of that vertex's color, while a sample near the center receives a mixture of all three colors. This produces a smooth gradient across the triangle.

Task 5: "Pixel sampling" for texture mapping

Pixel sampling determines how a texture color is selected for a sample on a texture-mapped triangle. For every covered sample, I first calculated its barycentric coordinates. I used those coordinates to interpolate the texture coordinates \(u\) and \(v\) from the texture coordinates stored at the triangle's three vertices.

After obtaining the interpolated texture coordinate, I converted it from the normalized range \([0,1]\) into coordinates in the full-resolution texture image. For Task 5, I always sampled mipmap level zero. The selected texture color was then written into the corresponding location in the supersample buffer.

Nearest and Bilinear Sampling

Nearest-neighbor sampling selects the single texel whose center is closest to the requested texture coordinate. It requires only one texture lookup, so it is fast, but it can create blocky edges and abrupt changes between neighboring texels.

Bilinear sampling uses the four texels surrounding the requested texture coordinate. I first interpolated horizontally between the two texels in each row and then interpolated vertically between the resulting colors. This produces smoother transitions, although it requires four texture lookups and additional interpolation.

Sampling Comparison

Comparison of Results

The nearest-sampled images show sharper but more abrupt transitions between texels. These artifacts are especially visible around detailed coastlines, thin lines, and regions viewed through the pixel inspector. Bilinear sampling blends neighboring texels, so these transitions appear smoother and less blocky.

Increasing the supersampling rate from 1 to 16 improves the rasterized edges of the triangles because more locations are sampled within each output pixel. However, supersampling and texture filtering solve different problems. Supersampling primarily reduces aliasing along triangle boundaries, while bilinear sampling reduces abrupt changes within the texture itself.

The difference between nearest and bilinear sampling is largest when the texture is magnified, when a sample falls between texel centers, or when the texture contains high-frequency details such as thin lines and sharp color boundaries. The difference can be less noticeable when the texture is viewed near its original resolution or contains large areas of nearly uniform color.

Task 6: "Level Sampling" with mipmaps for texture mapping

Level sampling chooses an appropriate mipmap resolution based on the size of a screen sample's footprint in texture space. When a large region of the original texture maps onto a small number of screen pixels, sampling only the full-resolution texture can skip many texels and create aliasing. A lower-resolution mipmap level contains a prefiltered version of the texture and produces a more stable result.

In my textured-triangle rasterizer, I calculated the interpolated texture coordinates at the current sample position, one screen pixel to the right, and one screen pixel downward. These values were stored in p_uv, p_dx_uv, and p_dy_uv. I used their differences to estimate how quickly the texture coordinates change across one screen pixel.

I scaled the horizontal texture-coordinate differences by the texture width and the vertical differences by the texture height. I then selected the larger of the two derivative magnitudes and calculated the mipmap level using:

\[ D = \log_2\left( \max\left( \sqrt{(W\,du/dx)^2 + (H\,dv/dx)^2}, \sqrt{(W\,du/dy)^2 + (H\,dv/dy)^2} \right) \right) \]

I clamped the resulting level to the range of available mipmap levels. For L_ZERO, I always sampled level zero. For L_NEAREST, I rounded the calculated level to the nearest integer. For L_LINEAR, I sampled the two surrounding mipmap levels and interpolated between their colors. Combining L_LINEAR with bilinear pixel sampling produces trilinear filtering.

Sampling Comparisons

I used the same custom PNG, viewpoint, zoom level, sample rate, and pixel inspector position for all four comparisons. This isolates the effects of the pixel- and level-sampling methods.

Comparison of Results

The L_ZERO and P_NEAREST result contains the most abrupt color changes because it selects one texel from the original full-resolution image. Switching to P_LINEAR smooths the transitions between nearby texels, but it can still show minification aliasing because it only combines four texels from level zero.

With L_NEAREST, the renderer chooses a prefiltered mipmap level whose resolution better matches the texture footprint of a screen pixel. This reduces high-frequency aliasing and unstable details when the texture is minified. Combining L_NEAREST with P_LINEAR additionally blends neighboring texels within the selected mipmap level, producing the smoothest result among these four configurations.

Speed, Memory, and Antialiasing Tradeoffs

Nearest pixel sampling is the fastest pixel-sampling method because it requires one texel lookup. Bilinear sampling requires four texel lookups and interpolation, making it slower but more effective at smoothing blocky transitions during texture magnification.

Level-zero sampling avoids the cost of calculating and selecting a mipmap level, but it can alias badly when a high-resolution texture is displayed at a small size. Nearest-level sampling adds derivative calculations and requires storing a mipmap pyramid, but it greatly improves texture minification. Linear-level sampling is more expensive because it samples two mipmap levels and interpolates between them. A complete mipmap chain also requires approximately one-third more texture memory than the original image alone.

Supersampling reduces aliasing by evaluating multiple sample locations inside each output pixel. It works on triangle edges as well as textured interiors, but both its running time and sample-buffer memory usage grow with the sample rate. In comparison, mipmapping is more specialized and memory-efficient for texture minification, while supersampling provides more general antialiasing at a higher computational cost.
